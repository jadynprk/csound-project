Making Music
with Your Hands

computational sound  ·  spring 2026  ·  Jadyn Park & Madeline Ou

A real-time tool to create music via drum beats and synths using hand gestures on a web browser. Built with React + JavaScript.

Audio

The full audio pipeline is built on Tone.js, a WebAudio API wrapper. Sound generation happens through two paths.

Drum samples are loaded into Tone.Players, which are containers that hold sound via a key/file path system — players.player("kick") retrieves the player and allows the audio to play immediately. Synth sounds come from Tone.PolySynth, a polyphonic synthesizer that generates audio mathematically in real time using oscillators and an amplitude envelope.

All sounds pass through a Tone.Limiter that caps output at a certain decibel level to prevent clipping, which then routes everything to Tone.Destination.

Timing is handled by Tone.Transport, which keeps a position that advances forward as audio runs, measured in bars, beats, and sixteenth notes. Tone.Transport.progress tracks position as a fraction of the entire measure. Tone.Sequence then schedules events based on the Web Audio hardware clock, allowing audio to be pre-scheduled to play at the right moment on the clock regardless of what JavaScript is actually doing.

UI

On top of a live camera feed, there exists a grid overlay where rows represent the different types of sounds and columns represent 16th notes. The grid is made up of two parts:

Grid.jsx — an invisible grid that divides the screen into row × column cells, with pixel coordinates handled by the browser. Each cell is toggled on when it receives a note. There are two separate grids: the drum grid has 4 rows (kick, snare, clap, hi-hat) and the synth grid has 7 rows (C D E F G A B).

ThreeCanvas.jsx — one large <canvas> element layered over the video that handles all visual components. When a dot is placed on a cell the area becomes 3D, and when the cell is played a burst animation occurs. To match coordinates between these two layers, ThreeCanvas reads the pixel position of each Grid cell and stores it in a cache. When cells toggle, ThreeCanvas draws visual elements at the exact cached coordinates.

When playing, a single vertical line sweeps through the grid horizontally to indicate which notes are being played. Its position is governed by Tone.Transport.progress — if 1 measure is 16 notes and the 8th note is playing, the bar sits at the halfway point. This allows the browser to be continuously resized without the play bar and audio drifting.

Pipeline

HandSyncSequencer.jsx functions as the pipeline by dictating all states — which cells are active, current mode, cursor position, and the active gesture. It routes gestures to their corresponding actions: peace sign places a note, both palms pause/play, pinky up switches between drum and synth mode.

useSequencer.js contains 4 important lines that define what a single measure looks like:

Tone.getTransport().bpm.value = BPM;  // sets the tempo
Tone.getTransport().loop      = true; // continuous loop
Tone.getTransport().loopStart = 0;    // starts at the beginning
Tone.getTransport().loopEnd   = "1m"; // ends after 1 measure

In Tone's notation, "1m" means one bar in 4/4 time, which at any BPM is always exactly 16 sixteenth notes. This is what allows Transport.progress to be tracked as a fraction of the measure. Using Tone.Sequence, on every 16th note it checks both grids and fires the corresponding audio at the exact time. Tone.Draw syncs the visual burst animations to the same moment.

MediaPipe

MediaPipe is Google's open source ML software library, especially good for computer vision. For hand tracking, we used the HandLandmarker model, which detects 21 landmarks per hand in real time — allowing very detailed hand tracking. It runs entirely client-side via WebAssembly, meaning no server, less latency, and no privacy concerns about streaming webcam data.

The MediaPipe Tasks Vision API's VIDEO running mode handles continuous streams where timestamps drive the inference loop, giving synchronous per-frame results that integrate cleanly with a requestAnimationFrame loop.

Architecture

The hand tracking layer is implemented as a React hook (useHandTracking), which accepts a video ref and a result callback. On mount, it loads the HandLandmarker model asynchronously from Google's CDN, then starts a requestAnimationFrame loop that calls detectForVideo on each frame, passing the current video element and a performance.now() timestamp. Results come back synchronously and are immediately passed to the callback.

Gesture Design

We split the two hands into distinct roles. The right hand acts as the cursor — the normalized x/y coordinates of landmark #8 (the index fingertip) map directly onto the sequencer grid. Because MediaPipe returns landmark positions as fractions of the frame dimensions (0–1) and the grid occupies the full viewport, no additional coordinate transformation is needed.

The left hand handles gestures. Gestures are defined by which fingers are extended, determined by comparing the y-coordinate of the fingertip to that of the proximal interphalangeal (PIP) joint. If the tip is above the PIP, the finger is extended.

  • peace sign Places and removes notes on the grid.
  • pinky up Switches modes between drums and synth.
  • both hands up Starts and stops the player. Takes priority over single-hand gestures.

Placing and removing notes works by mapping the right-hand fingertip to a grid cell and toggling it on a left-hand peace sign. The cursor coordinates are maintained in both React state (for rendering the visual crosshair) and a ref (for reading in the gesture handler without stale closure issues). A cooldown of 600ms prevents a single held gesture from toggling too quickly.

Integration with the Audio Layer

The hand tracking hook is intentionally decoupled from audio, which means the gesture dictionary can be extended without touching the audio pipeline. It produces two values per frame: a fingertip position and a gesture string. HandSyncSequencer maps these values to actions — cursor position updates React state, and gesture strings are compared in useEffect and dispatched to the appropriate handler.
